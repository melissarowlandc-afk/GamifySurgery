## Completion protocol

1. Create a NEW standalone Codex thread with a bounded scope, owned paths,
   requirements, non-goals, acceptance criteria, validation commands, and the
   applicable ExecPlan. Do not use `collaboration.spawn_agent` in this PM thread.
2. The task thread preserves unrelated work, validates its result, and records
   an exact handoff and handles technical review within its standalone scope.
   The owner works directly with that thread and tells the PM when it is done.
3. Mark the task **awaiting owner acceptance** and present a concrete result.
4. Once the owner agrees that task is complete, the current standing user
   instruction authorizes that task thread to audit and commit its scoped
   changes, push a GitHub backup, and verify the remote commit. No additional
   magic phrase is required. This overrides older handoff wording requiring
   the owner to say "push to GitHub" again.
5. Record branch, commit, verification, and handoff before archival. A backup
   does not authorize merging to `main`, Pages publication, or a release.
6. Archive the completed task thread after the verified backup. Never archive
   this ongoing PM thread as part of completing a delegated task.
