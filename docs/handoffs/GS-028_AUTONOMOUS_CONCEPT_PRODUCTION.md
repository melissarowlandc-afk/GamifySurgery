## Durable authoring rules

- One narrow primary Tested Concept per scored node and one stable FSRS identity
  per concept. Do not redefine existing meanings. Cosmetic patient changes do
  not create mastery exposure or solve patient supply; a material concept or
  answer-essential presentation change requires a new identity/version.
- Use one named fictional patient with explicit, coherent age, sex, pronouns,
  and existing compatible character. Chief complaints are normally 1–5 words.
  Keep complaint, presentation, and complete question distinct. Avoid abstract
  openings, answer/future-result leakage, detached definition quizzes, and
  unrelated reverse-direction patient lineups.
- Four substantively varied variants per new concept are the default. Use
  clinically purposeful one-to-three-node flows and genuine result gates only;
  never add testing merely to lengthen a visit or delay emergency escalation.
  Returned information must precede the next decision.
- Every scored question is single-select with exactly one defensible correct
  answer. Choices need parallel grammar, category, specificity, and comparable
  length. Runtime ordering shuffles. Feedback explains the answer boundaries
  and explicitly names the correct text after a wrong answer.
- Every testing choice, including distractors, repeats, surveillance, and
  sampling, needs a neutral centralized runtime estimate. These are gameplay
  placeholders, never clinical claims or authored prose. Do not use timing or
  route availability to reveal the key. Preserve the mixed/no-test convention.
- First submission alone updates FSRS: correct is Good and incorrect is Again.
  Corrected-forward teaching is not a second review and follows the authored
  correct route/gate instead of performing the incorrect choice.
- Onsite care requires actual supported capability, reachable access, staff,
  capacity, and route. Use a valid external/referral path when appropriate; do
  not invent onsite capability. Keep acuity, educational tier, capability,
  progression, and editorial weights separate.
- Preserve existing IDs, frozen encounters, pending requests, saved routes/due
  times, identity, choice order, and prior content. No web or model calls occur
  during gameplay.
