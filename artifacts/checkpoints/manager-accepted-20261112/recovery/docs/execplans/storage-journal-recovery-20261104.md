## Implementation and recovery contract

- Native full candidate preparation is now paced to once per 60 foreground seconds (`localJournal.ts:19`, `gameSession.ts:211`). The first dirty batch prepares immediately; explicit, day-end and fallback checkpoints bypass that preparation cooldown and capture the exact target. Cloud uploads still follow the approved five-minute/leaving/day-end/Save & Close policy and existing 60-second automatic-upload cooldown. One-second small journal commits do not wait for full preparation. A leaving callback does not upload a stale prepared ancestor; the newer committed tail remains recoverable on reopen (`gameSession.ts:232`).
- ACK and bounded pulse rebases keep current + prior full native snapshots, reclaim all move rows covered by the new snapshot, and delete obsolete packed evidence chunks. Rebind on reload also reclaims covered native rows after the selected state has been verified. Deletions occur before replacement allocation in the same IDB manifest transaction; abort rolls everything back. Legacy evidence journal suffix retention remains intact (`localJournal.ts:195-216,237-258`). Existing 512-command pulse bound remains; this milestone preserves that concurrent perf-lane change.
- Read-time reclamation allocates no replacement snapshot. It is idempotent and does not change the journal's manifest or invalidate the verified-copy memo. For old heads only, storage inspects the seed's native policy; the codec returns a small `snapshotOnly` proof flag to the cache. Optional reclamation failure is logged and does not itself invalidate an otherwise verified copy. No protected campaign/recovery store is an eviction target.
- `storageRetry.ts` distinguishes `CloudCacheError("timeout")` from real `quota`, retries exact IDB work after 250 ms / 1,000 ms, and keeps the existing enclosing cache-operation deadline at 30 seconds. Entry reads/writes/CAS, cache reads/writes/inventory and journal transactions preserve the cause. The enclosing deadline is deliberately not longer than a cancelled opening: a 45-second draft caused the existing missing-write regression to hold the local queue after a 30-second opening cancellation; it was corrected, with the original deadline assertion retained.
- One journal drain retains its immutable rows/rebase job on timeout and automatically retries with exponential backoff capped at ten seconds. It accepts commands only while its queue is below 128 and the coordinator's original authority gates allow them. At the queue bound play is visibly fenced; a successful commit releases that bound immediately. Actual quota/permanent errors still fence. In-memory pending work is never labelled durable (`localJournal.ts:475-536`, `gameSession.ts:159-164`). Storage cannot guarantee a normal one-second dirty age while the browser is refusing operations; the visible notice tells the player to keep the app open.
- A cache deadline may leave exact attempted bytes while the independent small journal remains healthy. Those bytes are persisted/read back before replacing a following candidate or sending any immutable operation (`coordinator.ts:642,683`). Same-byte retries are accepted only following this invocation's own timed-out put; an independent same-byte caller still loses the CAS (`cache.ts:146-168`). Network, writer generation, revoked/deleted, lease expiry and integrity gates remain unchanged.
- A healthy small drain or later preparation does not clear the retry cooldown while an immutable cache write is still attempted. Successful cache persistence clears that delay without emitting a new revision before ACK receipt listeners have advanced the session's bound revision. The controlled regression asserts no extra ordinary retry/write and one original immutable operation after explicit recovery, with no stale processing failure afterward.
- `CloudSaveControls.tsx:26-30,99-102` says "Free storage" only for actual browser quota (`storageQuota`). Timeout retries say "Device saving is delayed. Keep this app open while it retries." Other storage errors no longer speculate about space. The existing status/report presentation remains visible in both shells.
- Related diagnostics-only scope: `problemDiagnostics.ts` now accepts the already emitted native snapshot/tail counters and new storage flags in its bounded previous-session schema, plus committed/high-water/rebase counters. This fixes an additional discovered issue: an otherwise valid previous report containing native fields was discarded at restart. No clinic bytes, answers, IDs, tokens or new personal data are added. The persisted diagnostic limit stays 3,072 characters.
- On next load the existing automatic selector reconstructs the newest verified snapshot + committed journal, ranks it against account/retained copies, reclaims its own fenced writer lease and binds a fresh full baseline. The regression simulates an abrupt kill with no lifecycle callback, reconstructs an independent runtime over the same durable stores, compares the **entire exact state including campaign ID**, and uploads once. Nothing deletes the campaign, unique protected copies, uncertain requests or uncommitted in-memory rows. Normal crash loss remains at most the last uncommitted batch; failing storage necessarily leaves the clearly reported bounded pending batch in memory until it can commit.

No RPC, SQL, database schema, account/local save format or domain assertion changes. No clinical/question/character file changed. The perf worker concurrently added `prepareSnapshotTick` integration in `gameSession.ts`; those two hunks are preserved and excluded from this milestone's scoped implementation diff.
